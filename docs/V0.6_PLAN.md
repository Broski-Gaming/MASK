# MASK v0.6 — Technical Plan: Distributed MORP Relays (private testnet)

> **Status: plan only, not started.** v0.6 moves MORP relays from one
> computer to **several Linux computers that you control**, on a private
> network. There is **no public deployment** in v0.6: relays, directories,
> and services refuse public IP addresses by design. Nothing here makes MASK
> anonymous or production-ready; it remains an unreviewed experiment.

Prerequisite: v0.5 verified on 2026-11-01 (see `docs/PROGRESS.md`,
"v0.5 verification").

---

## 1. Goals

1. Run entry, middle, exit, and rendezvous relays, the directory, hidden
   services, and MASK Browser on **2–5 separate Linux machines** on a LAN or
   private VPN, with `.morp` sites working across machines.
2. **Authenticated, encrypted links** between every pair of MORP nodes, bound
   to relay identities, so a network attacker cannot impersonate a relay,
   inject `Destroy`, or read link metadata such as circuit IDs.
3. **Secure relay discovery**: clients and relays learn the relay list from
   signed, expiring consensus documents produced by directory authorities
   whose keys are pinned, instead of a shared folder.
4. Keep everything that already works: MORP circuits, hidden services,
   cryptographic-only `.morp` addresses (unchanged format), browser
   behaviour, and the no-direct-connection guarantee.

## 2. Non-goals (v0.6)

- Public internet deployment, public relays, or exit traffic to the internet.
- Anonymity claims. A testnet run by one person is not anonymous.
- Fixed-size cells and padding (planned separately; see §11).
- Browser UI changes beyond error messages.
- Changes to the `.morp` address format.

## 3. Starting point (what v0.5 has)

| Area | v0.5 | Gap for multiple machines |
|---|---|---|
| Addresses allowed | loopback only (bind, advertise, extend) | need private-network addresses |
| Links | plain TCP, self-declared roles | anyone on the network can read sizes/IDs, inject `Destroy`, claim any role |
| Relay discovery | JSON files in `runtime/directory/` | must work across machines and be tamper-proof |
| Service directory | single in-memory HTTP server, plain HTTP lookups | reachable over the network; lookups reveal interest |
| Config | command-line flags | per-machine config files |
| Path selection | random per role | must avoid two hops on the same machine |
| Intro points | host exits if lost | real networks drop links; must re-establish |
| Bind vs. published address | `advertise` option added in v0.5 verification | already usable |

## 4. Architecture

```
          ┌────────────── pinned authority keys (network.toml) ──────────────┐
          ▼                                                                   ▼
   ┌──────────────┐  signed consensus   ┌──────────────┐   ┌──────────────┐
   │ authority A  │◄──── votes ────────►│ authority B  │   │ authority C  │
   │ (machine 1)  │                     │ (machine 2)  │   │ (optional)   │
   └──────┬───────┘                     └──────────────┘   └──────────────┘
          │ consensus (signed by ≥ threshold authorities)
          ▼
 relays on machines 1–N  ◄═══ Noise-authenticated links ═══►  relays
          ▲                                                     ▲
   MASK Browser (client)                               hidden-service host
```

- **Directory authorities** (new binary `mask-authority`): a small set (1–3)
  of nodes run by the operator. Each has a long-term Ed25519 authority key.
  Their public keys and addresses are pinned in a `network.toml` that every
  machine gets out-of-band (copied by the operator).
- **Relays** upload signed descriptors to every authority. Authorities admit
  only relays on an operator **allowlist** (Sybil control for the testnet),
  test reachability, and sign a **consensus**: the list of admitted relays
  with their identities, link keys, roles, addresses, and machine families.
- **Clients, relays, and services** fetch the consensus, verify it, cache it,
  and use it for path selection and link authentication.
- **Links** between any two MORP nodes use the **Noise protocol** with keys
  bound to relay identities.

## 5. Workstreams

### 5.1 Network scope: private addresses only

- Replace the loopback-only checks with a `NetworkScope` setting:
  - `loopback` (default, v0.5 behaviour);
  - `private`: RFC 1918 IPv4 (10/8, 172.16/12, 192.168/16), IPv4 CGNAT
    100.64/10 (Tailscale-style VPNs), IPv6 ULA fc00::/7, plus loopback.
- Every bind, advertised address, `EXTEND` target, intro/rendezvous relay,
  directory/authority address, and service app address is checked against
  the scope. **Public addresses are always refused in v0.6.**
- Links are refused from peers outside the scope (checked on accept).
- Tests: scope classification table; refusal of public addresses everywhere.

### 5.2 Configuration files

- `relay.toml`, `authority.toml`, `service.toml`, `client.toml` (Serde +
  `toml`), with command-line overrides. Fields: nickname, role, listen,
  advertise, data directory, network scope, `network.toml` path, family.
- `network.toml`: network name, authority public keys and addresses,
  consensus threshold. Distributed manually; it is the trust anchor.
- Example configs and `systemd` unit files under `deploy/` (no secrets).

### 5.3 Authenticated links (Noise)

- Use the maintained `snow` crate (Noise Protocol Framework). Confirm current
  maintenance and audit status before adoption; fall back to `rustls` with
  raw public keys if `snow` is unsuitable.
- Each relay gets a **link key** (X25519 static) certified by its Ed25519
  identity: `Sign(identity, "MORP-v2 link key" || link_pub || expiry)`,
  published in its descriptor and the consensus.
- Patterns:
  - **client → entry**: `Noise_NK` (client knows the entry's link key from
    the consensus; client stays anonymous at the link layer);
  - **relay → relay**: `Noise_KK` or `IK` (both sides authenticated by link
    keys from the consensus). Inbound relay links from keys **not in the
    consensus are refused**, which removes v0.5's self-declared-role gap.
- After the handshake every `LinkMsg` travels inside Noise transport messages
  (≤ 65 535 bytes; MORP frames are already ≤ 64 KiB). The existing MORP
  circuit crypto is unchanged; Noise adds a second, link-level layer.
- Key rotation: link keys expire (default 7 days) and are re-certified.
- Tests: MITM proxy (reuse the v0.5 malicious-proxy harness) cannot complete
  or alter a handshake; unknown relay keys are refused; tampered transport
  messages close the link; downgrade to plain TCP is impossible.

### 5.4 Directory authorities and consensus

- `mask-authority` (Axum over the Noise link, or HTTP inside Noise):
  - `POST /v1/descriptors`: relay uploads a self-signed descriptor (identity,
    link key cert, role, advertised address, family, published, expiry).
  - Admission: identity on `approved-relays.toml`; address in scope; link
    handshake to the advertised address succeeds (reachability test).
  - Every period (default 10 min) each authority signs a **vote**; with
    several authorities, they exchange votes and each signs the
    deterministic **consensus** (sorted relays admitted by a majority).
  - `GET /v1/consensus`: latest consensus with all collected signatures.
- Consensus format: `valid_after`, `fresh_until`, `valid_until`, network
  name, sorted relay entries, authority signatures. Clients require
  signatures from ≥ `threshold` pinned authorities, `now < valid_until`, and
  a newer `valid_after` than their cached copy (no rollback).
- Retire `runtime/directory/` for networked use (keep it for the
  single-machine `loopback` scope and tests).
- Tests: forged, under-signed, expired, rolled-back, and wrong-network
  consensuses are rejected; non-allowlisted relays are never listed; a
  single compromised authority cannot add relays when threshold ≥ 2.

### 5.5 Hidden-service directory on the testnet

- Run the service directory on authority machines (one per authority),
  reachable only over Noise links.
- Hosts publish descriptors to all of them; clients query any one and
  verify as today.
- Stretch goal: fetch descriptors **through a MORP circuit** (a directory
  command at a rendezvous-role relay co-located with the directory) so the
  directory does not learn which client asked.
- Re-establish lost introduction points and republish the descriptor
  instead of exiting (carry-over from v0.5).

### 5.6 Path selection across machines

- Relays declare a **family** (operator-assigned machine ID) in their
  descriptor; authorities include it in the consensus.
- Path rules: no two hops from the same family; client's rendezvous point
  and the service's intro points chosen across families when possible.
- **Entry guards**: clients keep the same entry relay for a configurable
  period (persisted in `runtime/guards.json`) to limit exposure.
- Tests with multiple loopback addresses (127.0.0.2 … 127.0.0.9) standing
  in for different machines.

### 5.7 Operations

- `systemd` units with hardening (`DynamicUser`, `ProtectSystem=strict`,
  `NoNewPrivileges`, state in `StateDirectory`).
- Firewall guide (`nftables`): MORP ports open only to the private subnet.
- Clock sync requirement (`chrony`/`systemd-timesyncd`); consensus and
  descriptor checks already tolerate 5 minutes of skew.
- Status commands: `mask-relay status`, `mask-authority status`.
- Logs never contain keys, cookies, or content (existing rule).

## 6. Milestones (in order; each verified before the next)

| | Milestone | Done when |
|---|---|---|
| A | Network scope + config files + advertise | Relays/services/browser run from TOML configs; public addresses refused everywhere; tests pass |
| B | Noise-authenticated links | All MORP links use Noise; MITM, unknown-key, and tamper tests pass; v0.5 suites still pass |
| C | Directory authority (single) + consensus | One `mask-authority` admits allowlisted relays; clients/relays/services use the signed consensus |
| D | Multiple authorities + threshold signatures | 2–3 authorities agree on a consensus; under-signed/rollback tests pass |
| E | Multi-machine path rules, guards, intro re-establishment | Family rules and guards tested with multi-loopback simulation |
| F | LAN trial | Documented run on 2–5 real machines: `.morp` site on machine X opened in MASK Browser on machine Y through relays on other machines; results recorded in `docs/PROGRESS.md` |

## 7. Testing strategy

1. **In-process tests** (CI-friendly): multiple loopback addresses as
   "machines", deny-by-default `ConnectPolicy`, relay `Observer`, counters,
   and the malicious-proxy harness from v0.5.
2. **Network namespaces or containers** (manual, needs root or podman):
   one namespace per "machine" on a virtual bridge with private addresses,
   to exercise real routing and firewall rules.
3. **Real LAN trial** (milestone F) with a written checklist, including
   `ss` checks that browsers only connect to their entry relay.
4. **Fuzzing** (`cargo-fuzz`) of every decoder: `LinkMsg`, `LayerBody`,
   relay and service descriptors, consensus, Noise framing.

## 8. Security considerations

- The `network.toml` trust anchor must be distributed securely (copy it
  yourself; never fetch it over the network).
- Authority private keys are the most sensitive secrets in the testnet: mode
  0600, separate machines where possible, never committed.
- Allowlisting relays prevents strangers joining the testnet but means the
  operator controls every relay: **no anonymity against the operator**.
- Noise protects link contents and authenticity, not traffic analysis.
- A threat model update (`docs/MORP_TESTNET.md`) is part of milestone F.
